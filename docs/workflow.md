# 完整制作方法

1. 明确观众、用途与发布目标。列出真实项目链接和可演示版本。每项能力写为“功能 → 操作 → 可见变化 → 对照条件 → 镜头 → 旁白 → 验证依据”。使用 `skills/mod-skill-video-producer/assets/shot-plan.example.json`。
2. 盘点现有截图、录像、工程和已选择音色。先录短片并查看原尺寸，再批量录制。游戏 framebuffer 录制只在隔离副本和专用存档运行；浏览器或桌面录制按实际捕获范围检查遮挡。项目录制桥会修改专用存档，不能用于玩家正式存档。
3. 镜头按“效果吸引 → 多形态 → 有意义对照 → 真实调参 → 安装/开源入口”安排。宽盘面的横版素材在竖版中完整展示；长条效果按主体裁切。UI 可以上下重排，不把横版直接居中裁成竖版。
4. 文案用连续完整句子，解释变化和用途。配音原速试听确认音色，再按实际音频时长安排镜头。ASR 辅助定位错读，最终仍试听。不把社区模型说成剪映官方同名声音。
5. Remotion 中把每个需要独立编辑的镜头写成独立 JSX 节点，动画以帧驱动。使用项目锁定版本，打开 Studio 保持可预览。普通模板从 `templates/remotion-showcase` 开始，真实多片段时间轴参考历史 example。
6. 音乐记录来源、许可、署名和修改，旁白段压低 BGM。没有合适配音时先完成无配音预览，不擅自购买服务。
7. 封面从实际录像选峰值帧，做多形态拼接和真实 UI。检查原尺寸与 320×180 缩略图。封面变更不重复渲染整片。
8. 导出后检查分辨率、帧率、音轨、时长及完整解码，按章节查看代表帧、听取旁白与音乐。`inspect_video.py` 只证明技术媒体条件，不证明内容覆盖。
9. 交付视频、封面、标题、简介、真实仓库/下载链接及声音来源。传播以真实演示、安装教程、开发者使用案例和问题反馈为依据，不承诺 Star 增长。

横版默认 1920×1080/30fps；竖版默认 1080×1920/30fps，是制作起点而非平台强制规则。发布操作需用户授权，平台要求在发布时核对。
